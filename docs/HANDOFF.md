### 판정 결과: FAIL

전체 표본만 보면 PASS(percentile 100)였다. 폴드별로 뜯으니 3/4 폴드에서 전략과 랜덤 널이 소수점 넷째 자리까지 같았다. 전체 "엣지"는 폴드 3(최근 2년) 하나의 방어 효과가 만든 착시였고, 그 구간조차 절대값이 음수다. 플라시보는 정상 FAIL 이라 파이프라인 누수는 없다.

자세한 수치는 `docs/research/2026-08-17-baseline-verdict.md`.

**이게 왜 좋은 소식인지:** ①층이 바닥에 확정됐으므로 뉴스·LLM 층이 보이는 판별력은 전부 텍스트 정보의 기여로 분리 측정된다. 그리고 "거래대금이 급증했다"만으로는 40일 뒤가 안 갈린다 = **무엇 때문에 급증했는지가 필요하다**는 것이 데이터로 확인됐다. 이 프로젝트가 뉴스로 가는 이유다.

## 밤새 내가 내린 판단 (되돌리고 싶으면 말해라)

1. **계획 1 에 진단 태스크를 추가**했다. 원래 계획에 스펙 §10-3(손 안 댄 최종창)을 판정하는 단계가 없었다. 이게 없었으면 FAIL 을 PASS 로 보고할 뻔했다.

2. **최종 판정을 네 조건 AND 로 강제**했다 — 전체 널 대비 / 모든 폴드 널 대비 / 손 안 댄 최종창 / 플라시보 FAIL. 전체 평균 하나로 PASS 를 선언하는 경로는 코드에 없다.

3. **초과수익 벤치마크를 업종에서 횡단면 동일가중 평균으로 변경**했다. `sector_index` 가 2024-01-26 부터만 존재해 전 기간을 못 덮는다.

4. **신용잔고 피처를 범위에서 제외**했다. `credit_balance` 가 2026-02-20 부터로 6개월치뿐이다. 공매도도 2024-05 부터라 전 기간 피처로는 못 쓴다.

5. **계획 3 의 뉴스 어댑터를 계획 2 의 정규화 스키마에 맞춰 수정**했다. 계획 2 가 `articles` + `article_codes` 로 나눈 게 옳다(기사 1건이 여러 종목에 걸린다). 어댑터 SELECT 에서 조인·별칭으로 흡수한다.
