계획 2 Task 1 이 유일한 사람 개입 지점이다. 로그인·다운로드는 자동화하지 않기로 했다.

1. https://www.bigkinds.or.kr 회원가입·로그인
2. 뉴스 검색에서 아무 조건이나 걸고(예: 최근 1주일 · 경제 분야) 결과를 **엑셀로 다운로드**

본 수집은 그다음이다. 1회 20,000건 제한이 있어 날짜 구간을 나눠 여러 번 받아야 한다.

*(Task 3·5·6 — 종목 마스터 로더, 중복 제거, 핫함 계산 — 은 이미 구현돼 있다.)*

### 2. LLM API 키 발급

계획 3 이 요구한다. provider 는 환경변수로 교체 가능하게 설계돼 있으니 하나만 있으면 된다.

- 기본 권장: Gemini 최저가 등급(Flash-Lite 급). 기사당 작업이 "제목+리드 읽고 고정 스키마 채우기"라 추론 난이도가 낮다.
- 키는 `.env` 에 넣는다 (`.gitignore` 차단됨).

첫 실행은 반드시 `--limit` 을 작게 잡고 시작하도록 CLI 가 설계돼 있다.

배선은 이미 확인됐다. 키 없이 이렇게 돌려볼 수 있다:

```bash

  --start 2026-08-01 --end 2026-08-14
```

키가 생기면 `--provider gemini` 로 바꾸고 `--limit 20` 부터 시작하면 된다.

### 판정 결과: FAIL — 단, 한 번 정정했다

**첫 측정(`top_n=15`)은 잘못 쟀다.** 하루 후보가 중앙값 8건인데 상위 15를 고르니
`selection_ratio = 1.0` — 대부분의 날짜에 후보 전체를 담았다. 선택이 일어나지 않았으니
전략과 랜덤 널이 정의상 같았다. 스펙 §2 의 "동시 보유 15종목"을 "날짜당 15종목"으로
구현한 것이 원인이다. 40거래일 보유이므로 동시 보유 ≈ `top_n × 40` 이고 `top_n=1`
이어도 40종목이다.

사전등록(`docs/research/2026-08-17-topn-preregistration.md`) 후 `top_n=2` 로 **한 번만**
재측정했다:

| | top_n=15 | **top_n=2** |
|---|---|---|
| 전체 | +0.59% · net +0.13% | **+2.22% · net +1.76%** (pct 100) |
| 폴드 0 / 1 / 2 / 3 (널 대비) | ❌ ❌ ❌ ✅ | ✅ ❌ ❌ ✅ |
| 손 안 댄 최종창 | −1.08% **FAIL** | +4.06% · net **+3.60% PASS** |
| 플라시보 | FAIL(정상) | FAIL(정상) |
| **종합** | FAIL | **FAIL** (폴드 1·2 미달) |

**종합은 여전히 FAIL 이고 그 판정을 뒤집지 않는다.** 4개 구간 중 2개에서 재현되지
않는 것을 엣지라고 부를 수 없다. 다만 "수급 단독은 무력하다"는 더 이상 사실이 아니다.
정직한 요약은 **레짐 의존적인 신호가 있고 아직 재현되지 않는다** 이다.

자세한 수치는 `docs/research/2026-08-17-baseline-verdict.md`.

**다음 층의 과제가 구체적으로 정해졌다:** ①층이 바닥이 아니라 실재하는 선이 됐다.
특히 **폴드 1·2(평범한 시장 구간)에서 널을 이기는 것** — 그 두 구간에서 수급만으로는
아무것도 못 골랐다. "무엇 때문에 급증했는가"가 필요하다는 원래 가설은 그대로 서 있다.

## 밤새 내가 내린 판단 (되돌리고 싶으면 말해라)

1. **계획 1 에 진단 태스크를 추가**했다. 원래 계획에 스펙 §10-3(손 안 댄 최종창)을 판정하는 단계가 없었다. 이게 없었으면 FAIL 을 PASS 로 보고할 뻔했다.

2. **최종 판정을 네 조건 AND 로 강제**했다 — 전체 널 대비 / 모든 폴드 널 대비 / 손 안 댄 최종창 / 플라시보 FAIL. 전체 평균 하나로 PASS 를 선언하는 경로는 코드에 없다.

3. **초과수익 벤치마크를 업종에서 횡단면 동일가중 평균으로 변경**했다. `sector_index` 가 2024-01-26 부터만 존재해 전 기간을 못 덮는다.

4. **신용잔고 피처를 범위에서 제외**했다. `credit_balance` 가 2026-02-20 부터로 6개월치뿐이다. 공매도도 2024-05 부터라 전 기간 피처로는 못 쓴다.

5. **계획 3 의 뉴스 어댑터를 계획 2 의 정규화 스키마에 맞춰 수정**했다. 계획 2 가 `articles` + `article_codes` 로 나눈 게 옳다(기사 1건이 여러 종목에 걸린다). 어댑터 SELECT 에서 조인·별칭으로 흡수한다.

6. **`swing-score` 의 가격 룩백 버그를 고쳤다.** `--start` 부터만 가격을 읽어 `adv`
   롤링 창이 안 차서 **이벤트가 항상 0** 이 되고 모든 기사가 `no_volume_event` 로
   조용히 탈락했다. 실패가 아니라 정상 종료로 보여서 더 위험했다. 실 DB 스모크에서
   31배 급증일 기사가 탈락하며 발견. 수정 후 같은 조건에서 이벤트 0 → 343건.

7. **`features/llm.py` 소유권을 계획 3(Task 8)으로 정했다.** 처음엔 계획 4 에 두라고
   지시했는데, 계획 3 쪽 설계가 더 나았다 — 컬럼별 `max` 집계 대신 대표 기사 한 건의
   행을 통째로 쓴다. 컬럼별로 접으면 A기사의 구체성과 B기사의 감정이 섞인, 실재하지
   않는 기사가 만들어진다.
