# 만쥬 원형 복원 + 알고리즘 수급 반전 — 사전등록 (76번)

> 2026-09-15 작성, **수익률 계산 전 커밋**. 설정·특징 정의·창·문턱 결정 규칙·선택
> 목적함수·게이트를 여기서 고정한다. §0~§11 은 측정 후 수정하지 않는다. 결과는 맨 아래
> "측정 결과" 제목 밑에만 붙인다.

## 0. 왜 재나

[75번](75-tick-replay-optimization-preregistration.md)은 라이브 규칙을 틱·호가로
리플레이해 기각했다. 청산 사유를 뜯어 보면 손실 대부분이 두 규칙에서 나온다.

- **−0.5% 후속주 가격 손절**: 중앙 20초 만에 나간다. 진입이 대장 "근접" 단계라 굳힘
  통보 전이고, 그래서 `--stop-needs-leader-weak` 잠금이 걸리지 않는다.
- **본절탈출**(1호가·30초): 선택 셀 OOS 96건 중 25건.

둘 다 만쥬 규칙이 아니다. 본절탈출과 정점이익 50% 반납은 타 트레이더 B 것이고
([45번](45-manju-parity.md) 출처 주의), 만쥬는 "2등주 가격 지표로 손절하지 말라"고
했다([46번](46-manju-answers.md) §12-3). 라이브에는 그 밖에도 만쥬와 다른 값이 있다.
국면 정지 5조(만쥬 7~8조), `--max-roundtrip-bp 30`(45번 문서 기준 20),
`min_sl_ticks 3`(우리가 만든 값).

두 번째 질문은 사용자가 설명한 만쥬의 핵심 엣지다. 진입 순간에 **기관 수급이 돌아서는
것**을 본다. 기관은 초단타 알고리즘으로 1초 안에 몰아서 산다("1초 안에 다라락"). 알아보는
단서는 체결량이다. 사용자 원문(2026-09-15):

> "체결량인데 1초 안에 와라락 나오거나, 비슷한 숫자가 여러 번 비슷한 패턴으로 나오는 거야."

그래서 이 연구는 두 가지를 잰다.

1. **B(만쥬 원형)** 가 A(라이브)와 어떻게 다른가. 서술용이고 채택 판정에 쓰지 않는다.
2. B 거래 안에서 **알고리즘 체결 패턴 ON 이 OFF 보다 나은가**. 이것이 주 가설이다.

## 1. 표본 — 75번과 같다

```
전체  2026-08-24 ~ 2026-09-14 (틱 있는 16거래일)
IS    08-24, 08-25, 08-26, 08-27, 08-28, 08-31, 09-01, 09-02
```

### 1-1. 국면 — 이 표본에서 만쥬 국면 평가는 불가능하다

75번 퍼널 표에 적힌 전일 코스닥 거래대금(라이브 게이트 기준) 16일 중 **8조 이상은 2일**
(09-09 8.15조, 09-11 11.42조)뿐이다. 두 날 모두 OOS 다. 7조 이상으로 넓혀도 3일

- **"5조 라이브" 관점**: 전일 거래대금 < 5조면 신규 진입 0. **주 판정은 이 관점으로 한다.**

  미리 적어 둔다.
- 따라서 이 연구의 결과는 거의 전부 **"만쥬라면 쉬었을 날"** 의 것이다. 통과해도
  "만쥬 규칙이 맞다"는 증거가 아니고 "침체장에서도 이 패턴이 통했다"는 뜻일 뿐이다.

## 3. 알고리즘 체결 특징 — 정의 고정

### 3-1. 공통 규칙(선견 금지)

- 신호 시각 `t` = 후보 알림의 초 단위 시각. 저장 틱에는 밀리초 시각이 없고, 캐시에는
  방아쇠를 당긴 틱의 `seq` 가 없다.
- **보수 규칙: 신호가 난 초 전체를 뺀다.** 모든 창은 `ts < t` 인 틱만 쓴다. 같은 초에서
  방아쇠 틱보다 앞선 체결도 버린다. 결과적으로 가장 최근 정보가 최대 1초 늦어진다.
- 호가(`quotes`)는 특징에 쓰지 않는다.
- 방향: `side=+1`(매수 공격, FID 15 부호 +)만 "매수 체결"로 센다. `side=0/None` 은 어느
  쪽에도 넣지 않는다.
- 초 안의 순서는 `seq` 다. "1초 안에 몇 건"은 같은 `ts` 초의 행 수를 센다(한 행 = 한 체결 통보).
- 대장과 후속주 **각각** 계산한다.
- 창 표기 `[a, b)` 는 `t` 기준 초 단위 오프셋이다. 예: `[t−3, t)` 는 신호 직전 3개 초
  (t−3, t−2, t−1)다.

### 3-2. P1 — 1초 몰아치기(burst)

짧은 창 길이를 `W1` 이라 둔다.

```
last        = [t−W1, t)
baseline    = [t−W1−120, t−W1)                  120초
base_rate   = baseline 전체 체결 수 / 120        (초당 평균, 0 인 초 포함)
burst_cnt   = max_{s ∈ last} (그 초의 매수 체결 수)
burst_sec   = 위 최대를 낸 초(동률이면 가장 늦은 초)
burst_net   = burst_sec 의 Σ side·price·volume   (부호 있는 체결대금, 원)
p1_ratio    = burst_cnt / max(1.0, base_rate)
P1 ON  ⇔  burst_cnt ≥ 3  AND  p1_ratio ≥ θ1  AND  burst_net > 0
```

"비교 기준선의 중앙값" 대신 **평균**을 쓴다. 소형주는 초당 체결 수 중앙값이 대부분 0 이라
분모가 무의미해지기 때문이다. 하한 1.0 도 같은 이유다.

### 3-3. P2 — 비슷한 수량 반복(slicing)

긴 창 길이를 `W2` 라 둔다.

```
창          = [t−W2, t) 의 매수 체결 중 volume ≥ 10주      (1~9주 잡음은 제외)
유사        = |v − v_ref| ≤ max(1주, 0.05·v_ref)
클러스터    = 창 안의 각 서로 다른 수량 v_ref 마다 유사한 체결 모음 → 건수 최대인 것
              (동률이면 v_ref 가 큰 것)
p2_count    = 그 클러스터 건수 k
p2_secs     = 클러스터가 걸친 서로 다른 초 수
p2_gap_cv   = 클러스터의 서로 다른 초들 사이 간격의 변동계수(표준편차/평균; 초 3개 미만이면 ∞)
P2 ON  ⇔  p2_count ≥ max(4, θ2)  AND  p2_secs ≥ 3  AND  p2_gap_cv ≤ 1.0
```

- "여러 초에 걸쳐 비슷한 리듬으로"를 **서로 다른 초 3개 이상 + 간격 CV ≤ 1.0** 으로
  고정한다. 한 초 안에서만 반복되는 것은 P1 몫이다.
- 10주 하한과 ±max(1주, 5%) 허용폭은 측정 전에 정한 값이고 조정하지 않는다.

### 3-4. P1∧P2, REV(반전)

```
P12  ⇔  P1 ON AND P2 ON                     (같은 창 조합)
REV  ⇔  net([t−W2−30, t−W2)) < 0            ("직전 30초 순매도")
        AND net([t−W2, t)) > 0              ("최근 순매수")
        AND (P1 ON OR P2 ON)
net(창) = Σ side·volume (주)
```

### 3-5. 창 조합 — 2개로 고정

```
짧은 조합  S: W1 = 3s,  W2 = 10s
긴 조합    L: W1 = 10s, W2 = 30s
```

### 3-6. 문턱 θ1·θ2 결정 — 수익률을 보지 않는다

- θ1 = **IS 8일 전체 후보**(B 리플레이 후보 전부, 필터·게이트 적용 전)의 `p1_ratio` 75%
  분위수. 역할(대장·후속)·창 조합별로 따로 구한다.
- θ2 = 같은 집합의 `p2_count` 75% 분위수. 역시 역할·창 조합별로 따로 구한다.
- 분위수 계산에는 틱·후보만 쓰고, 수익률 열은 읽지 않는다.
- 값은 결과에 적는다. 한 번 정하면 OOS·대조군·서술 절에 그대로 쓴다.

### 3-7. 시행 수

```
특징   P1 · P2 · P12 · REV            4
창     S · L                          2
역할   대장 · 후속                    2
                                      = 16 시행 (전부 원장 기록)
N(DSR) = 16 + 48(75번) + 30(54번 누적) = 94
```

설정 A·B 비교는 서술용이라 N 에 넣지 않는다. 대신 병기용 N = 96(두 설정 포함)과
N = 334(manju 최적화 240셀 포함)도 적되, 판정은 94 로 한다.
원장: `research/logs/76-algo-flow/TRIALS.jsonl` (`krx_quant_core.stats.trials.record_trial`).

## 4. 거래 집합 두 개

- **주 집합 (B-필터)**: B 설정 필터·게이트 전부(cap 20·depth on·minsl 0·10:00 컷오프·
  5조 국면)를 통과하고 through 체결된 거래.
- **넓은 집합 (B-넓음)**: B 청산 규칙은 같지만 필터·컷오프·국면을 전부 끈 거래(through
  체결). 75번 표로 보면 B-필터의 IS 거래는 10건 안팎이다(cap 30·minsl 0 셀이 IS 12건).
  이 수로는 특징 16개 중 하나를 고를 수 없다. 그래서 **선택은 넓은 집합의 IS 에서** 한다.
  특징의 의미는 필터와 무관하다.

## 5. 비용 — 75번 PRIMARY 그대로

- 청산가 = 가드 청산 시각의 직전 매수1호가(없으면 체결가).
- 순수익 = 청산매수호가/진입지정가 − 1 − `round_trip_cost(그날, 시장, commission_rate=0.00015)`.
  세금은 날짜를 반영하고, 수수료는 0.015%×2 다.
- 체결 가정은 through, 체결가는 지정가(+2호가)다. touch 는 병기만 한다.

## 6. IS 선택 — 고정

- 대상: B-넓음 · IS 8일 · 16 시행.
- 목적함수: **ON 건평균 순수익 − OFF 건평균 순수익**.
- 자격: IS ON n ≥ 10 AND OFF n ≥ 10 AND 목적함수 > 0.
- 선택: 자격 시행 중 목적함수 최대인 **하나**. 동률(소수 6자리)이면 §3-7 나열 순서
  (P1<P2<P12<REV, S<L, 후속<대장)에서 앞선 것을 고른다.
- 자격 시행이 없으면 **선택 없음**. 판정은 "기각(IS 에서 신호 없음)"이다. OOS 는 서술용
  ON/OFF 비율만 계산하고 수익률 표는 만들지 않는다.

## 7. OOS 평가 — 한 번

선택된 특징 하나를 OOS 8일에 적용한다.

- **주 판정**: B-필터 거래의 ON 부분집합. 보조로 B-넓음 ON 부분집합도 같은 표에 싣지만
  판정에는 쓰지 않는다.
- 다른 15개 시행의 OOS 표는 만들지 않는다.

## 8. 채택 게이트 — AND, OOS, 주 판정 집합(B-필터 ON)

1. OOS ON **n ≥ 30**. 미달이면 "**표본 부족 — 판정 불가**"로 쓰고 나머지는 참고로만 보고한다.
2. ON 순수익 **평균 > 0 AND 중앙값 > 0**.
3. **날짜 클러스터 부트스트랩**(OOS 날짜 복원추출, 10,000회, seed 76) 평균의 95% CI 하한 > 0.
4. **ON 이 OFF 를 이긴다**: 같은 날 ON·OFF 가 모두 있는 날짜로 짝지은 일평균 차이
   (`paired_date_bootstrap`, 10,000회, seed 76). p = P(차이 ≤ 0) < 0.05.
5. **무작위 대조군을 이긴다**: 각 ON 거래의 같은 시각에 구독 중이던(±60초 내 틱) 다른
   종목 하나를 seed 로 고정해 뽑는다. 같은 대장, 같은 B 청산, 같은 비용을 적용하고 특징
   조건은 요구하지 않는다(75번 대조군과 같은 방식, B 청산으로 다시 돌린 것).
   날짜 짝 부트스트랩 p < 0.05.
6. **Deflated Sharpe 확률 > 0.95** — `deflated_sharpe_from_sample(OOS ON 건당 순수익, N=94)`.
7. **주 빼기 검증**: OOS 날짜를 달력 주 3개(09-03·04 / 09-07~11 / 09-14)로 나눈다. 한 주씩
   뺀 나머지의 ON 평균이 음수인 경우 ≤ 1.

전부 통과하면 "채택(그림자 비교 단계로)"이고, 하나라도 떨어지면 "기각"이다. 1번 미달이면
2~7번과 무관하게 "표본 부족 — 판정 불가"다.

## 9. 서술 — 선택·판정에 쓰지 않음

- **B vs A (16일 전체)**: 건수, 평균, 중앙값, 청산 사유 분포. 5조·8조 관점 모두 적는다.
  유의성 판정은 하지 않는다.
- **패턴 빈도**: 16일 전 후보 시점에서 P1·P2·P12·REV ON 비율을 대장·후속·S·L 별로 센다.
  비교 대상은 두 종류의 무작위 시점이다. (a) 같은 종목의 같은 날 09:00~15:20 중 무작위

## 10. 채택·기각의 의미

- 채택은 즉시 라이브 변경이 아니다. 그림자 기록 1주 후 사용자가 결정한다.
- 기각이면 기록하고 멈춘다. 창·문턱·허용폭을 바꿔 다시 재지 않는다. 새 데이터(밀리초
  수신시각, 투자자별 체결, 프로그램 원자료)가 생기면 새 사전등록으로 한다.
- B vs A 는 서술이다. B 가 A 보다 좋아 보여도 이 문서로는 라이브 청산을 바꾸지 않는다.

## 11. 미리 밝히는 한계

- **시각이 1초 해상도다.** 밀리초 수신시각이 없어서 "1초 안에"는 같은 `ts` 초 안의 행 수로만
  잴 수 있다. 초 경계에 걸친 몰아치기는 둘로 쪼개진다. 체결 통보가 묶여 한 행으로 올
  가능성도 확인하지 못했다.
- **리플레이 패리티가 1~2/3 이다**(75번). 이 연구는 저장 틱 유니버스에 규칙을 적용한
  반사실을 잰다.
- **프로그램 수급 게이트를 재현할 수 없다.**
- **투자자 신원 정보가 없다.** "기관 알고리즘"은 체결 패턴에서 추정한 것일 뿐이다. 개인의
  분할 매수 앱이나 외국계 창구도 같은 모양을 만들 수 있다.
- **표본 대부분이 8조 미만인 날이다**(§1-1). 만쥬가 쉬라고 한 날들이다.
- 신호가 난 초 전체를 버리므로, 방아쇠와 같은 초에 터진 몰아치기는 못 본다. 결과를
  보수 쪽으로 편향시킨다.
- B-필터 OOS 거래가 30건에 못 미칠 가능성이 높다(75번 cap 30 셀도 OOS 27건). 그러면 ON
  부분집합은 더 작다. 표본 부족 판정도 유효한 결과로 기록한다.

## 사전등록과 달라진 점

- **판정 기준은 그대로다.**
- 코드 버그 하나를 고쳤다. 특징 캐시 레코드의 `leader`/`follower` 키가 특징 dict 로
  덮여서 선택 단계의 무결성 assert 가 실패했다. 수익률을 계산하기 전(원장 기록 전)에
  멈췄고, 코드는 B 캐시에서 붙이도록 고쳤다. 특징 값은 바뀌지 않았다.
- 무작위 대조군 종목은 75번 리플레이와 같은 seed(75) 문자열로 뽑혔다(`replay_day` 내부).
  부트스트랩 seed 는 76 이다.
- 사용자가 준 패턴 정의(P1 몰아치기 / P2 비슷한 수량 반복)는 사전등록 커밋 **전에** §0·§3 에
  반영했다. 커밋 뒤 따로 보강한 내용은 없다.

## 해석

1. **만쥬 원형 청산(B)도 음수다.** 가격손절과 본절탈출을 빼면 손실 청산이 "180초
   시간청산 평균 −0.46%"로 옮겨 갈 뿐이다. 재난선(−2.36%)은 필터를 끈 집합에서 23건
   나왔다. 추세청산(+3% 무장)은 265건 중 9건뿐이다. **진입가(+2호가) 위로 가격이 안
   간다는 75번의 구조 문제는 청산 규칙을 바꿔도 남는다.** 대장이탈 청산도 22건
   −0.40%로 구하지 못한다. B 가 A 보다 조금 나은 것(+7bp)은 비용·호가 청산에 먹히는
   수준이다.
2. **후속주 1초 몰아치기(P1·L·후속)는 방향이 맞는 쪽으로 움직였다.** 필터를 끈 OOS 에서
   ON 은 OFF 보다 +0.31%p, 같은 시각 무작위 종목보다 +0.73%p 나았다. ON 의 세전 평균은
   +0.04% 로 0 근처다. 그러나 순수익은 여전히 −0.23% 이고, DSR 확률 0.0008,
   주를 하나씩 빼도 3번 모두 음수다. **"덜 나쁘다"이지 "돈이 된다"가 아니다.**
   IS 에서 이 시행을 고른 근거도 ON 10건이었다. 무작위 대조군 대비 p 가 낮게 나온 데는
   대조군 자체가 B 청산(가격손절 없음)으로 −0.98% 까지 나빠진 영향도 있다.
3. **REV(순매도 → 순매수 반전 + 패턴)는 IS 에서 8개 시행 전부 ON 이 OFF 보다 나빴다**
   (−0.20%p ~ −0.91%p). "수급이 돌아서는 순간"을 직전 30초 순매도로 정의하면 반대로
   작동한다. 이미 매도 공격을 받던 종목의 짧은 반등을 잡는 셈이다.
4. **P2(비슷한 수량 반복)는 이 정의로는 대부분 10~12주짜리 소량 클러스터를 잡는다.**
   예시 3건 모두 기준 수량이 ≈11주였다. 017670(08-24) 예시에서는 `+10 +11 … -1 -1 +21`
   이 매초 거의 같은 순서로 반복된다(간격 CV 0.18). 눈으로 봐도 기계 주문이다. 반면
   290660·0197V0 처럼 초당 100건씩 체결되는 종목은 10~12주 체결이 우연히 쌓여도
   k 가 100 을 넘는다. **P2 는 활동량과 섞여 있다.** 사용자가 말한 "비슷한 숫자"가
   수백~수천 주 단위라면 이 정의(10주 하한·±5%)로는 그걸 따로 떼어 보지 못한다.
5. **P1 예시 1번(032820 09-08 09:11:22)은 VI 해제 단일가 체결로 보인다.** 직전 2분
   (09:09:20~09:11:20) 동안 체결이 0건이었고, 해제 초에 92건이 한꺼번에 찍혔다. 기관 알고가
   아니라 단일가 매칭이다. 선택된 P1·L·후속은 16일 전 후보 중 ON 44건이고, 그중 기준선 0 인 경우가 없었다(최소
   0.11건/초). 그래도 P1 정의는 VI 해제를 알고 체결과 구분하지 못한다.
6. **1초 해상도의 한계가 실제로 보인다.** 체결이 활발한 대장주는 평소에도 한 초에 20~40건이
   찍힌다(후보 시점 중앙 20건). "1초 안에 다라락"을 행 수로 세면 대장에서는 신호가
   거의 안 드러난다. P1·S·대장 IS ON−OFF −0.09%p 였다. 밀리초 수신 시각이 있어야 "한
   초 안에서도 수십 ms 에 몰렸다"를 볼 수 있다.

## 권고

- **라이브 청산을 B 로 바꾸지 않는다.** 이 표본에서 B 도 음수이고 A 와의 차이는 비용 이하다.
- **알고리즘 체결 게이트를 라이브에 넣지 않는다.** 주 판정은 표본 부족이고, 보조 집합에서도
  순수익이 음수다. 다만 "후속주 직전 10초 한 초 몰아치기"가 OFF·무작위보다 덜 나빴다는
  점은 **그림자 기록 대상**으로 남길 가치가 있다. 라이브 알림에 `p1_ratio`·`burst_cnt` 를
  찍기만 하고 판정에는 쓰지 않는다. 20~30일 뒤 **새 사전등록**으로 다시 본다.
- 이 가설을 제대로 재려면 **새 데이터**가 필요하다. 재튜닝으로는 안 된다.
  1. 수신 시각 밀리초(수집기에서 `time.time_ns()` 저장) — P1 을 1초 안 몰림으로 재정의
  2. 투자자별·창구별 체결 데이터 — "기관" 추정을 확인
  3. VI 발동·해제 시각 — P1 에서 단일가 체결 제외
  4. 사용자가 눈으로 본 **실제 사례 시각·종목 5~10건**. 그 사례의 수량 규모(수십 주인지
     수천 주인지)를 보고 P2 허용폭·하한을 **측정 전에** 다시 정한다
- 진입 구조(+2호가 지정가 → 가격이 진입가 위로 안 감)는 75·76 두 번 연속 같은 결론이다.
  다음 사전등록 1순위는 여전히 **진입 시점 축(근접 vs 굳힘 확인 후)** 이다.
