# 만쥬 진입 시점 — 상한가 3호가 근접 vs 잠김 확인 후 — 사전등록 (79번)

> 2026-09-15 작성, **수익률 계산 전 커밋**. 팔(arm)·청산 계열·거래 집합·선택 목적함수·
> 게이트를 여기서 고정한다. §0~§10 은 측정 후 수정하지 않는다. 결과는 맨 아래
> "측정 결과" 제목 밑에만 붙인다. (77·78번은 다른 연구자가 같은 날 진행 중이다.)

## 0. 왜 재나

[75번](75-tick-replay-optimization-preregistration.md)과 [76번](76-manju-pure-algo-flow-reversal-preregistration.md)이
같은 곳을 가리켰다. 손실은 필터·청산이 아니라 **진입 구조**에서 나온다. 대장이 상한가
3호가 앞(아직 안 잠김)일 때 후속주를 +2호가에 사면, 체결 후 MFE 중앙값이 0이고 −0.5%
손절이 중앙 20초 만에 난다. 76번 B(가격손절·본절탈출 끔)로 바꿔도 손실이 시간청산으로
옮겨갈 뿐이었다.

만쥬 원문은 진입 시점을 두 갈래로 말한다.

| 읽기 | 원문 | 출처 | 등급 |
|---|---|---|---|
| **근접** | "대장이 상한가 호가를 3개 남겨둔 3~5초 사이에 매수" | 46 §2, 45 대조표(`--limitup-near-ticks 3`) | A |
| **근접**(다른 표현) | "20%대 중후반에서 상한가로 치고 들어가는" | 44 §5-1 묶음 6 | A |
| **안착/굳힘** | "상한가에 **안착**하거나 상한가 직전 급등" | 44 §5-1 묶음 1 | A |
| **굳힘 확인** | "순간 체결량 창으로 대장주에 대량 자금이 몰려 **상한가를 굳히는지** 확인" | 44 §5-1 | B |

`pair_detector` 독스트링도 "원자료가 터치인지 잠김인지 확정되지 않아(§11 #4)"
`limitup_touch`/`limitup_near_*`/`limitup_lock_secs` 를 따로 켤 수 있게 뒀다고 적는다.
44번 §11 #4 는 이 구분을 "자동화에 치명적"이라 했다. 이 연구는 **만쥬 원문 읽기 사이의
선택**이다. 임의 튜닝이 아니다.

## 2. 팔(arm) — 만쥬 읽기만, 최대 4

라이브 방아쇠(측정 전 코드 확인, `pair_detect_daily.sh`):
`--limitup-near-ticks 3 --limitup-require-surge --vi-near 0.01 --big-trades 2`
(대량체결 = 5천만원 이상 한 건, 창 30초 — `DetectorConfig` 기본값) `--lock-min-krw 300000000`
(상한가에서만 벽 3억 확인), `--cosurge 0 --premove 0.002`, `--entry-ticks-up 2`.

| 팔 | 방아쇠 | 나머지 |
|---|---|---|
| **T1 근접(라이브)** | 상한가 3호가 이내 **또는** 정적 VI 상단 1% 이내, 서지 AND, 대량체결 2건/30초 | 라이브 그대로 |
| **T2 잠김 확인** | 대장 가격 ≥ 상한가가 **L = 3초** 이상 연속 유지(`limitup_lock_secs=3`), 상한가 매수벽 ≥ 3억(라이브 `lock_min_krw`), 서지 AND, 대량체결 2건/30초. `limitup_near_ticks=0`, `vi_near=0` | 진입 +2호가, 후속 조건(premove·cosurge·manju 서열) 라이브 그대로 |
| ~~T3 근접 + 순간체결량 확인~~ | **생략.** 라이브가 이미 `--big-trades 2`(5천만원 이상 2건/30초)를 걸고 있고, 45번 대조표가 이것을 "5천만 이상 (비공개 회신 — 공개본에서 뺐다) §4)의 배선으로 적었다. T1 과 같다 | — |
| **T4 잠김 확인 + 2등주 아직 안 뜀** | T2 후보 중 후속주 **직전 60초 수익률 < +2%** 인 것만 | T2 와 같음 |

- **L = 3초 한 값만 쓴다.** 출처: 만쥬가 굳힘 안정성을 코드화하라고 준 창이 "직전 **3초** 피크
  대비"(46 §5)이고, 진입 시점 표현도 "3~5초"(46 §2)의 하한이 3초다. 두 번째 값은 원문 근거가
  없어 넣지 않는다.
- **서지 AND 를 T2 에서도 유지한다.** 방아쇠의 시점 한 축만 바꾸기 위해서다. 부수 효과로
  잠긴 뒤 약 30초 안(서지 창)에만 발동한다. 30분 전에 잠긴 대장을 뒤늦게 사는 일은 없다.
- **VI 근접을 T2 에서 끈다.** 켜 두면 상한가 아래 가격에서 "VI근접"으로 발동해 잠김 확인이
  무의미해진다(감지기는 상한가에 붙은 건만 VI 재발동을 막는다).
- **T4 의 +2%**: 46 §2 "1분봉이 마감된 시점에는 이미 2등주가 **2~4%** 튀어 오른 뒤라 추격 매수
  시 100% 물립니다"의 하한. 60초 수익률 = 알림 시각 후속주 가격 / (알림 시각 −60초 이하 마지막
  체결가) − 1(감지기 `_price_at` 과 같은 정의, DB 틱으로 계산). 라이브 premove 는
  `[t−60, t−30]` 구간만 보고 최근 30초(cosurge 0 = 하한만)는 막지 않으므로 T4 는 T2 와
  다르다. 사후 필터라 쿨다운 소비는 T2 와 같다(75 §3 과 같은 한계).

## 3. 청산 계열 — 사전 선언된 요인, 시행 수에 넣는다

| 계열 | 내용 |
|---|---|
| **E-live** | 75번 라이브 가드: 약손절 −0.5%(`--stop-needs-leader-weak`), 재난선 −2%, 본절탈출 1호가·30초, 트레일 +3%/1.5%, 대장이탈(정체 15초·1호가 하락·벽 30% 감소 3초·매도폭탄 1억·풀림), 시간 180초 |
| **E-B** | 76번 B(만쥬 원형): 가격손절 없음, 본절탈출 끔, 나머지 E-live 와 같음 |

⚠️ **측정 전 코드 확인 사실**: 가드의 손절 잠금 플래그 `leader_holding` 은 감지기의 굳힘
통보(**상태 전이 순간에 한 번**)를 받을 때 **이미 열려 있던** 포지션에만 켜진다. 잠김 확인 뒤
여는 T2·T4 포지션은 통보가 이미 지나가서 E-live 에서 −0.5% 손절이 **잠기지 않는다**. 라이브에
T2 를 넣으면 실제로 이렇게 돈다. 리플레이는 이 동작을 그대로 잰다(src 수정 없음). E-B 는 가격
손절이 없어서 영향이 없다.

시행 = 팔 3(T1·T2·T4) × 청산 2 = **6**. 전부 `research/logs/79-entry-timing/TRIALS.jsonl` 에
`krx_quant_core.stats.trials.record_trial` 로 기록한다.

## 4. 거래 집합

- **주 집합 P**: depth_short 배제 on(만쥬 최우선 필터), `max_roundtrip_bp` off, `min_sl_ticks` 0,
  컷오프 없음, 국면 게이트 off. through 체결 거래.
  - 이유: 75번에서 필터를 풀어도 부호가 안 바뀌었고(48셀 전부 음수) 라이브 셀 OOS 가 24건이라
    진입 시점 축을 가를 표본이 없다. 진입 시점은 필터와 독립인 축이다. 두께 배제만 만쥬 원문
    최우선이라 남긴다.
- **보조(판정 안 씀)**: 계열 고유 셀 — E-live 는 75 `LIVE_CELL`(cap30·depth on·minsl3·10:00·5조),
  E-B 는 76 `CELL_B`(cap20·depth on·minsl0·10:00·5조). 선택 시행과 기준선에 대해 OOS 에서만 싣는다.

## 5. 비용·체결 — 75번 PRIMARY 그대로

- 진입 지정가 = 알림 순간 후속주 현재가 + 2호가. 체결 = through(체결가 < 지정가), 체결가 = 지정가.
  180초 안에 미체결이면(또는 대장이탈로 소멸) 거래 아님. touch 병기.
- 순수익 = 청산 시각 직전 매수1호가 / 지정가 − 1 − `round_trip_cost(그날, 시장, 수수료 0.015%)`
  (1주 실전 비용, 날짜별 세율).
- **체결률** = P 집합 단계 통과 후보 중 through 체결 비율. 팔별·IS/OOS 별로 보고한다.

## 6. IS 선택 — 고정

- 목적함수: **IS 일평균 순수익**(P·through·PRIMARY) = 거래 있는 IS 날의 "그날 평균"의 평균.
- 자격: IS 거래 **n ≥ 10**.
- 선택: 자격 시행 중 목적함수 최대 하나. 동률(소수 6자리)이면 T1<T2<T4, E-live<E-B 순서로 앞선 것.
- 자격 시행이 없으면 선택 없음 → OOS 는 기준선만 계산, 판정 "표본 부족 — 판정 불가".

## 7. OOS — 한 번

- 선택 시행 하나와 **기준선 T1×E-live**(P 집합, 그리고 보조로 LIVE_CELL)만 OOS 를 계산한다.
  다른 시행의 OOS 수익률 표는 만들지 않는다.

## 8. 채택 게이트 — AND, OOS, 선택 시행, P·through·PRIMARY

1. **OOS n ≥ 30**. 미달이면 "**표본 부족 — 판정 불가**"(나머지는 참고).
2. 순수익 **평균 > 0 AND 중앙값 > 0**.
3. **날짜 클러스터 부트스트랩**(OOS 날짜 복원추출, 10,000회, seed 79) 평균 95% CI 하한 > 0.
4. **무작위 대조군을 이긴다**: 75번 대조군(같은 시각 구독 중 다른 종목, 같은 대장·같은 청산 계열·
   같은 비용). 날짜 짝 부트스트랩(10,000회, seed 79) p = P(차이 ≤ 0) < 0.05.
5. **Deflated Sharpe 확률 > 0.95** — `deflated_sharpe_from_sample(OOS 건당 순수익, N)`,
   **N = 6 + 30(54번 누적) + 48(75) + 16(76) + (OOS 계산 시점에 `research/logs/77*`·`78*`
   원장이 있으면 그 줄 수)**. 실제 N 을 결과에 적는다.
6. **주별 폴드**: 16일 전체를 달력 주 4개로 나눠 주별 평균이 음수인 주 ≤ 1(거래 0건 주 제외).

전부 통과 = "채택(그림자 비교 단계로)", 하나라도 실패 = "기각", 1번 미달 = "표본 부족".

## 9. 서술 — 선택·판정에 쓰지 않음

- **패리티**: 새로 돌린 T1×E-live 후보열을 75번 캐시와, T1×E-B 를 76번 B 캐시와 날짜별로 대조
  (후보 수·시각·대장→후속·진입가). 다르면 적는다.
- **MFE 분포**(16일 전체, 팔×청산, P·through 체결 거래): 중앙값, MFE = 0 비율, MFE ≥ +0.5%·+1%·+3%
  비율, 청산 사유, 보유 초. 핵심 질문: 잠김 확인 뒤 사면 "진입가 위로 안 간다"가 달라지나.
- **팔별 후보·체결 퍼널**(날짜별 후보 → P 단계 → 체결).
- **국면 분할**: 전일 코스닥 거래대금 5조 미만/5~8조/8조 이상(8조 이상은 09-09·09-11 두 날뿐).
- T1 후보 중 대장이 알림 뒤 180초 안에 실제로 상한가 3초 잠김에 도달한 비율(T1 과 T2 의 관계).

## 10. 채택·기각의 의미와 한계

- **채택 시 즉시 라이브 반영(사용자 지시 2026-09-15).** 그림자 주간 없음. 결과에는 통과한
  팔×청산을 `pair_detect_daily.sh` 플래그(파서에 실재하는지 확인한 값)로 옮긴 매핑, 또는 코드로
  없는 부분을 정확히 적는다. 이 연구가 라이브 코드·런처를 직접 고치지는 않는다.
- 기각·표본 부족이면 기록하고 멈춘다. L·X 를 바꿔 다시 재지 않는다.
- 한계(미리 밝힘): 리플레이 패리티 1~2/3(75번) — 저장 틱 유니버스 반사실이다. 프로그램 수급
  게이트 재현 불가. 호가는 초당 마지막 스냅샷이라 3초 잠김·벽 3억 판정이 초 단위로 거칠다.
  1초 해상도라 "3~5초 전" 진입의 초 안 순서를 모른다. 16일 중 8조 이상 2일 — 만쥬 국면 평가 불가.
  E-live 에서 T2·T4 손절 잠금이 안 걸리는 것은 라이브 가드 동작 그대로다(§3). 잠김 뒤 +2호가
  지정가는 상한가 근처 후속주가 이미 뛰었으면 미체결이 늘 수 있다(체결률로 보고).
