# 필터배제 반사실 — 왕복충격 문턱은 데이터로 어디까지 여나 (74번)

> 2026-09-10 새벽 작성. 사용자 지시 "데이터 기반 파인튜닝 시작". 측정 스크립트
> `scripts/filter_counterfactual.py`, 산출물 `data/filter_counterfactual_20260825_20260909.md`.
> 사전등록이 아니라 **사후 복기**다 — 이미 옮긴 문턱(20→30bp, 09-09)을 데이터로
> 되짚는 것이라 판정선은 "추가 완화 근거가 있나"로만 둔다.

## 0. 왜 재나

09-09 저널: 진입 5건, 필터배제 21건. 그 전날들도 같은 꼴이다(09-07 37건, 09-08 40건).
배제 사유의 84%(115/137)가 `roundtrip_bp`(1,000만원 시장가 왕복 충격 > 한도)다.
한도는 09-09에 20→30bp 로 옮겼는데 근거는 "표본을 늘리자"였지 배제된 신호가 실제로
어땠는지는 아무도 안 봤다. 여기서 본다.

## 1. 방법 — 그리고 한계

배제 통지(`pair_detect.log`)마다 후속주 체결(`ticks`)에 신호 시각을 얹어 라이브 청산
근사로 되돌린다:

```
진입     신호 직후 첫 틱, 진입가(통지의 '진입 N원' = 현재가+2호가) 즉시 체결
청산     재난선 −2% · 타임스탑 180s · 트레일(+3% 도달 후 고점 −1.5%)
변형     약손절 −0.5% 없음(대장 굳힘 중 손절 잠금 = 라이브 기본) / 항상 켬
비용     net64 = 수익 − 64bp.  net64+충격 = 거기서 잰 왕복충격까지 뺀 값
대조군   같은 기간 **통과한** 신호 7건(알림 JSON, rt_bp 기록됨)을 같은 시뮬레이터로
```

**못 흉내 내는 것:** 대장이탈 청산(대장 상태 미기록). 라이브 09-09 실적 5건 중
대장이탈 1건이 −0.72% 에서 잘랐고, 통과군 시뮬은 그걸 못 잘라 실거래(세전 +0.76%)보다
비관적(−0.44%)이다. **그래서 절대값이 아니라 구간 간 결 차이만 읽는다.**

**날짜 복원:** 통지엔 시각만 있고 날짜가 없다. `pair_detect.log` 의 `# 시황 — 날짜`
머리말은 stdout(블록 버퍼)이고 통지는 stderr 라 파일 안 순서가 섞여 표지로 못 쓴다.
통지 시각이 거꾸로 가는 곳을 세션 경계로 잡고, 세션마다 "그 통지들이 그 시각에 틱을
가진" 영업일을 골랐다(7세션 전부 적중률 ≥ 0.5, 미배정 0건).

표본: 배제 137 / 통과 7, 2026-08-31 ~ 09-09 7거래일.

## 3. 읽기

1. **추가 완화 근거 없음.** 30→40/50/60/100bp 어디를 열어도 추가 집합의 net64 는
   −0.46~−0.71%, 중앙값은 전부 음수. 평균이 양수로 보이는 60bp+ 구간은 우측 꼬리
   몇 건(228340 +3.8%, 014950 +2.1%)이 끌어올린 것이고, 그 구간은 잰 충격 자체가
   수익을 다 먹는다(net64+충격 −1.0~−1.8%).
2. **09-09에 새로 연 20~30bp 구간이 오히려 가장 나쁘다.** 14건 승률 29%, 중앙 −0.57%,
   MAE 중앙 −1.10%(통과군 −0.64%의 두 배). 다만 n=14 이고 시뮬이 대장이탈을 못 잘라
   비관적이므로 **되돌릴 근거로는 약하다** — 되돌리려면 이 구간 실거래가 쌓인 뒤 본다.
3. `depth_short`(10호가로 1,000만원을 못 채움)는 1주 실주문엔 비용이 0 이라 평균은
   +0.73% 로 보이지만 MFE 중앙 0 — 17건 중 대부분이 안 움직였고 두어 건이 튀었다.
   호가 없는 종목의 복권이다. 필터 유지.
4. `min_sl_ticks` 7건 전부 음수 쪽. 필터 유지.

## 4. 결정 (2026-09-10 장 전)

- `--max-roundtrip-bp 30` **유지**. 더 열지 않는다(§3-1).
- 20~30bp 구간은 실거래 표본이 이 구간에서 10건 넘으면 다시 본다. 그때 net64 가
  통과군보다 뚜렷이 나쁘면 20bp 로 되돌린다.
- 이 측정을 매일 15:27 크론으로 돌려 `data/filter_counterfactual_latest.md` 에
  누적한다(일지 15:26 직후). 사람이 매번 안 돌려도 표본이 쌓이게.

## 5. 부수 발견 — 고침

- **일지가 날짜 없는 통지를 전부 '오늘'로 읽었다.** 09-09 일지에 09-01~08 배제 건이
  섞여 들어가 있었다(시각이 14:57 → 09:04 로 되돌아가는 대목이 그 흔적). 통지 레코드에
  `day` 를 남기고(`LogFileSink.notice`), 일지는 그날 통지만 읽게 고쳤다
  (`scripts/pair_journal.py`). 날짜 없는 옛 통지는 버린다 — 어느 날 것인지 알 수 없다.
- `pair_detect.log` 의 `#` 머리말(stdout)과 `[HH:MM:SS]` 통지(stderr)는 파일 안에서
  순서가 안 맞는다. 이 로그로 날짜를 복원할 땐 머리말을 믿지 말 것(§1).
