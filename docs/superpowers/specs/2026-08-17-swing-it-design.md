# swing-it — 설계 스펙

**작성일:** 2026-08-17
**상태:** 승인됨, 구현 계획 대기

---

## 1. 무엇을 만드는가

한국 주식(KOSPI·KOSDAQ)에서 **2~8주 스윙 후보를 찾아주는 개인용 리서치 툴**.

매일 소수(10건 내외)의 "핫한" 기사를 재료로 삼아, 그 재료가 몇 주 갈 추세인지를 판정하고,
근거와 함께 후보 종목을 제시한다. 최종 매매 판단은 사람이 한다.

**한 줄 요약:**

> 기사에서 재료를 찾고 → LLM 이 구조화 피처로 변환하고 → 수급이 독립 확증하고 →
> ML 이 D+20~40 초과수익으로 학습하고 → kr-quant 게이트가 심판하고 →
> 통과한 것만 후보 리스트로 나온다.

**나중에 공개 레포로 전환할 계획.** 설계가 이를 전제한다(§8).

## 2. 왜 이 모양인가 — 두 번의 실패에서 온 제약

이 설계는 백지에서 나온 게 아니라 두 번의 부정 결과 위에 서 있다.

**(a) Minervini 리더 시스템 (실패).** 수정주가 미반영 데이터가 만든 아티팩트였다.
분할 조정 후 다시 재니 시가총액 가중 지수를 못 이겼다(+14.0%/Sharpe 0.54 vs +15.5%/0.71).

**(b) 프랍 스윙 엣지 탐색, 2026-07-18 (실패).** 롱온리·1~10일·4~8종목 집중으로
돌파·눌림목·PEAD집중 세 셋업을 심사했고 **셋 다 자기 랜덤-진입 널조차 못 이겼다.**
그 문서의 결론이 남긴 세 갈래:

> (a) 다른 데이터(장중·대체데이터) (b) 일봉에 없는 엣지원 — **촉매/뉴스/재량**
> (c) 분산 PEAD 를 받아들이되 그건 프랍이 아님

**swing-it 은 (b) 노선이다.** 우연이 아니라 그때 남긴 결론을 따라간다.

여기서 세 가지 강제 조건이 나온다. 위반하면 같은 결과가 나온다:

1. **드리프트를 자르지 않는다.** PEAD-집중이 죽은 직접 원인은 10% 손절 + 10일 캡이
   승자를 자르고 노이즈를 확정한 것. 목표 보유 20~40 거래일, 짧은 캡 금지.
   근거 카드에 손절가를 표시하더라도 그것은 개별 리스크 관리이지 시그널 엑싯이 아니다.
2. **집중하지 않는다.** 4~8 종목은 이미 죽은 영역. 동시 보유 15종목 이상을 전제로 제시한다.
3. **음성대조 없이 아무것도 승격하지 않는다.** 프랍 탐색에서 판별기 역할을 한 것은
   폴드 수가 아니라 **랜덤 널 대비**였다. 표본이 작을수록(§6) 더욱 그렇다.

## 3. 핵심 구조 — LLM 은 피처 추출기, ML 은 학습기

역할 분리가 이 설계의 중심축이다.

### LLM 이 하는 일: 기사 → 구조화 피처 (판정하지 않음)

기사 하나당 고정 스키마를 채운다:

| 피처 | 내용 |
|---|---|
| 재료 유형 | 수주 / 실적 / 신약 / 증설 / 정책 / 테마 / 루머 … |
| 지속성 단서 | 일회성 이벤트인가, 분기 이상 실적에 반영될 건인가 |
| 구체성 | 금액·기간·계약처가 명시됐는가, "추진 검토" 수준인가 |
| 신선도 | 새 정보인가, 이미 알려진 내용의 반복인가 |
| 감정 | 방향과 강도 |
| 규모 대비 | 시총·매출 대비 얼마나 큰 건인가 |

**LLM 에게 "이거 오를까?"를 묻지 않는다.** 그 답을 믿는 순간 검증이 불가능해진다.

### ML 이 하는 일: 피처와 실제 결과를 대조해 학습

라벨은 가격 데이터에서 공짜로 나온다:

> 기사 게재 **D+1 시가 진입** → **D+20 ~ D+40 초과수익** (시장·업종 대비)

이 구조 덕분에 검증이 표준 지도학습 문제가 된다 — walk-forward, 음성대조, 비용스윕을
kr-quant 게이트로 그대로 적용할 수 있다. LLM 의 주관은 시그널이 아니라 입력일 뿐이다.

**부수 효과: "하루 뛰고 마는 것"이 자동으로 걸러진다.** 라벨이 D+20~40 이므로
당일 급등 후 되돌리는 재료는 학습 과정에서 음수 라벨을 받는다. 규칙으로 배제할 필요가 없다.

### 수급: 텍스트와 독립된 두 번째 증거

재료 강도를 기사 텍스트만으로 판단하면 결국 기자의 어조를 읽는 것에 가깝다.
수급 데이터가 이를 보완한다.

| 피처 | 의미 |
|---|---|
| 기관·외국인 순매수 (D+1~D+5) | 스마트머니가 실제로 따라 들어왔는가 |
| 대차잔고·공매도 변화 | 반대 베팅이 늘었는가 |
| 거래대금 급증 배수 | 관심도, 유동성 확보 |
| 신용잔고 | 개인 레버리지 유입 — 과열 경고(음의 피처 가능성) |

**검증 가능한 핵심 가설:** "LLM 이 강하다고 본 재료 중, 기관·외국인이 따라 들어온 것만
20~40일을 간다." 두 축이 독립이라 과적합 검출이 쉽다.

수급은 장마감 후 확정이므로 D+1 진입 기준으로 시점 안전하다. point-in-time 준수는
코드에서 강제한다(kr-quant lookahead 가드 재사용).

### 층별 기여도 분리

베이스라인부터 쌓아 각 층이 값을 하는지 따로 판정한다:

```
① 수급 단독                  ← 베이스라인. 텍스트 없이 얼마나 나오는가
② + 규칙 기반 뉴스 피처       ← 기사 건수·매체 수 등. LLM 없이
③ + LLM 구조화 피처           ← LLM 이 ①②를 이기는가
```

**③이 ②를 못 이기면 LLM 을 쓸 이유가 없다.** 이 비교를 강제해야
"LLM 썼더니 좋아졌다"는 착각을 막을 수 있다.

## 4. 데이터 소스

| 용도 | 소스 | 상태 |
|---|---|---|
| **과거 기사(학습)** | 빅카인즈 | 무료, 100+ 매체, 1990년대~현재. **본문 200자만**, 1회 20,000건 다운로드, 재배포 금지 |
| **실시간 기사(운영)** | `krx-news-rest-api` (자체) | 네이버금융·한국경제·더벨 크롤링 5분 주기, KIND+DART 60초. **본문 전문.** Redis TTL 뉴스 1시간 |
| 가격·수급·신용·공매도 | `quant-airflow` → TimescaleDB | 매일 적재 중 |
| 시세·수급 API | `kiwoom-rest-api` (자체) | 182 REST + 19 실시간 WebSocket. **뉴스 엔드포인트는 없음** |
| 검증 프레임워크 | `kr-quant` | walk-forward · DSR · 음성대조 · 비용스윕 |
| 공시 | DART Open API | 무료 REST, 완전 point-in-time |

### 결정 사항

**본문은 학습·운영 모두 200자 기준으로 통일한다.** 빅카인즈(200자)와
krx-news-rest-api(전문)의 입력 길이가 다르면 모델이 깨진다. 전문은 근거 카드 표시용으로만 쓴다.

이 제약은 생각보다 가볍다. 트레이더가 몇 초 만에 훑고 판단한다면 필요한 정보는
제목과 리드에 다 있다는 뜻이다. 깊게 읽는 모델이 얕게 읽는 사람을 못 이기면 그것도 결론이다.

**직접 크롤러를 새로 짜지 않는다.** krx-news-rest-api 가 이미 한다.
네이버·언론사 직접 크롤링은 ToS·저작권 리스크가 공개 전환 계획과 충돌한다.

**즉시 착수할 일 — krx-news-rest-api 영구 저장.** 현재 TTL 1시간으로 버려지는 데이터가
6개월 뒤 전진검증 자산이다. 지금 시작하지 않으면 6개월 뒤에도 시작할 수 없다.
이는 swing-it 이 아니라 krx-news-rest-api 쪽 변경이지만, 선행 조건이다.

**네이버 검색 API 는 쓰지 않는다.** 일 25,000건 제한은 충분하나 `start` 최대 1000 이라
과거 아카이브 용도로는 못 쓴다.

### '핫함'의 정의 — 과거와 현재가 동일해야 한다

백테스트 유효성의 핵심. 조회수처럼 과거 데이터가 없는 지표는 쓸 수 없다.
양쪽에서 동일하게 계산 가능한 것만 쓴다:

- 당일 해당 종목 **기사 건수**의 평소 대비 급증 배수
- **보도 매체 수** (여러 매체가 동시에 다뤘는가)
- **거래대금 급증 배수**

셋 다 빅카인즈·krx-news-rest-api·가격DB 양쪽에서 같은 방식으로 계산된다.

## 5. 유니버스

**고정 종목 리스트가 아니라 기사가 유니버스를 정한다.** 그날 유의미한 기사가 난 종목이
그날의 후보 풀이다. 소형주 재료도 자연스럽게 잡힌다.

단, **point-in-time 유동성 하한을 건다.** PEAD 검증에서 이 조건 없이는 소형주 꼬리가
노이즈를 주입해 시그널이 음수로 뒤집혔다. 못 사는 종목이 상위에 올라오면 무의미하다.

**수집 범위와 운영 범위를 분리한다:**

- **학습:** 일 30~50건 (표본 4배 확보, "핫함 순위" 자체가 피처가 됨)
- **운영:** 상위 10건 내외 (사람이 근거 카드를 직접 읽고 판단할 수 있는 규모)

## 6. 표본 크기 제약 — 모델은 단순해야 한다

일 30~50건 × 3년 ≈ 33,000~55,000 이벤트지만, 라벨 구간(D+20~40)이 겹치고
같은 날 이벤트끼리 시장 상관이 있어 **실효 독립 표본은 훨씬 적다.**

강제 조건:

- 피처 **10~20개**, 모델은 **GBM 또는 로지스틱 회귀** 수준
- **딥러닝·대규모 앙상블 금지** — 이 표본 크기에서는 과적합 기계
- **음성대조 게이트 필수** — 표본이 작을수록 우연히 좋아 보이기 쉽다
- 사전등록: 파라미터 그리드를 돌리기 전에 config 를 확정하고 기록

## 7. PEAD 의 위치

이 레포의 중심이 아니다. 두 자리에 남는다:

1. **모델 피처 하나** — 실적 서프라이즈 축
2. **비교 벤치마크** — 뉴스 모델이 이미 검증된 PEAD(Sharpe ~0.8, t≈2.2)를 이기는가

PEAD 자체를 스윙으로 이식하는 작업은 이 스펙 범위 밖이다.

## 8. 레포 경계와 모듈

### 기존 스택과의 관계

```
quant-airflow        수집 · 적재       → TimescaleDB (가격·수급·신용·공매도)
krx-news-rest-api    뉴스·공시 수집    → 실시간 (+ 영구저장 추가 필요)
kiwoom-rest-api      시세·수급·주문    → 182 REST + WebSocket
kr-quant             검증 프레임워크   → walk-forward · DSR · 음성대조
swing-it             제품              → 주간 후보 리스트 + 근거 카드
```

kr-quant 는 "검증 프레임워크지 스크리너 제품이 아니다"라는 정체성으로
2026-08-16 에 스크리너 CLI 7종을 제거했다. swing-it 이 그 빈자리인 **제품**이다.

### 모듈

| 모듈 | 책임 | 의존 |
|---|---|---|
| `adapters/` | 외부 레포 접근을 여기 한 곳에 격리 | kr-quant, kiwoom, krx-news |
| `news/` | 기사 수집·종목 매핑·중복 제거·point-in-time 저장 | adapters |
| `score/` | LLM 배치 피처 추출 (provider 교체 가능) | news |
| `features/` | 뉴스 피처 + 수급 피처 결합, 라벨 생성 | news, adapters |
| `model/` | 학습·추론 (GBM/로지스틱) | features |
| `validate/` | kr-quant 게이트 호출 | model, adapters |
| `report/` | 후보 리스트 + 근거 카드 | model, news |

**`adapters/` 규칙:** kr-quant·kiwoom·krx-news 에 손을 뻗는 코드는 전부 여기에만 둔다.
나머지 모듈은 그 레포들이 존재하는지도 모른다. 나중에 완전 독립 레포로 가려면
어댑터만 자체 구현으로 갈아끼우면 된다. 공개 전환 시에도 이 경계가 그대로 도움이 된다.

**`validate/` 규칙:** swing-it 은 자기 검증을 하지 않는다. 판정은 전부 kr-quant 게이트를
통과해야 하고, 통과한 것만 운영에 등록된다. 스크리너 안에 백테스트를 넣으면
반드시 자기 정당화를 시작한다.

### LLM provider 추상화

`score/` 는 provider 인터페이스 뒤에서 동작한다. Gemini / GPT / Claude 를 환경변수로 교체.

- 기본은 **최저가 등급**(Flash-Lite 급). 기사당 작업이 "제목+리드 읽고 고정 스키마 채우기"라
  추론 난이도가 낮다. 무거운 모델이 필요한 종류의 일이 아니다.
- 표본 수백 건만 상위 모델로 돌려 피처 품질을 대조한다. 차이가 없으면 싼 것으로 확정.
- 실제 단가는 착수 시점에 확인한다. 배치 API 할인 적용 검토.

### 공개 전환 전제

- **데이터는 절대 커밋하지 않는다.** 빅카인즈 재배포 금지, 기사 저작권. 구조로 강제(.gitignore + CI 체크).
- API 키·계좌 정보는 환경변수로만.
- 어댑터 경계 덕분에 코드만 공개하고 데이터·자격증명은 로컬에 남는다.

## 9. 범위

### 1차 범위 안

- 빅카인즈 과거 기사 인제스트 (수동 다운로드 → 정규화 적재)
- 종목 매핑, 중복 제거, '핫함' 계산
- LLM 배치 피처 추출 (provider 추상화)
- 수급·거래대금 피처 결합, D+20~40 라벨 생성
- 층별 모델 학습 (①수급 → ②+규칙뉴스 → ③+LLM)
- kr-quant 게이트 심판
- 후보 리스트 + 근거 카드 출력
- 오늘부터의 전진 기록(forward log)

### 1차 범위 밖 (나중)

- 실시간 WebSocket 모니터링, 진입 타이밍
- **조건검색** — 사람이 만든 조건식은 과적합 유입 경로. 학습된 모델이 자리잡기 전엔 쓰지 않는다
- 주문 자동 실행
- 뉴스 인제스트의 quant-airflow 이전 (자동화 가능해지면)
- 빅카인즈 유료 전문 라이선스 (200자로 부족하다고 *확인된 뒤에만*)

## 10. 성공 기준

이 프로젝트가 성공했다고 말할 수 있는 조건:

1. **층별 기여도가 분리 측정됐다** — 수급 단독 / +규칙뉴스 / +LLM 각각의 성과가 나왔다
2. **음성대조를 이겼다** — 랜덤 진입 널 대비 유의하게 우월
3. **walk-forward 재현** — 클린 OOS 폴드에서 재현, 손 안 댄 최종창에서도 양수
4. **비용을 견딘다** — 현실적 비용(왕복 46bp 이상)에서 여전히 양수
5. **PEAD 대비 판정이 나왔다** — 이기든 지든 명시적으로

**부정 결과도 성공이다.** 프랍 스윙 탐색이 그랬듯, "뉴스 재료 강도는 한국 시장
2~8주 지평에서 재현되는 엣지가 아니다"라는 결론이 나오면 그것을 기록하고 끝낸다.
세 번째로 아티팩트를 실전에 올리는 것보다 낫다.
