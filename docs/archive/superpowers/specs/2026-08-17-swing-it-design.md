**개정:** 2026-08-17 (rev2 — 이벤트 정의를 뒤집음. §0 참조)
**상태:** 승인됨, 구현 계획 대기

## 0. rev2 개정 요약 — 이벤트를 뒤집었다

**rev1:** 이벤트 = 거래대금 급증 → "왜 급증했나"를 재료로 설명
**rev2:** **이벤트 = 재료 발생(공시)** → 그 후 D+20~40 드리프트를 잰다

바꾼 이유 넷:

1. **검증된 알파가 이미 이 구조다.** PEAD 는 "실적 발표"라는 재료를 이벤트로 삼고
   그 후 드리프트를 먹는다. 이 프로젝트에서 유일하게 살아남은 형태다.
2. **자연 실험이 깨끗하다.** 공시 접수 시각은 정확한 정보 공개 시점이다.
   거래대금 급증은 원인이 아니라 결과라 시점이 흐릿하다.
3. **역인과를 피한다.** 급증한 종목의 재료를 찾는 것은 이미 오른 걸 보고 이유를
   붙이는 것에 가깝다.
4. **선별도가 확보된다.** rev1 은 하루 이벤트 23건 중 15개를 골라 `selection_ratio`
   가 1.0 이었다 — 선택이 일어나지 않았다
   (`docs/research/2026-08-17-topn-preregistration.md`).

**사용자의 실제 판단 흐름과도 일치한다.** 가격 순위를 훑는 게 아니라 공시·뉴스를 보고
종목을 찾는다고 확인됐다. 시스템이 같은 방향으로 돌아야 근거 카드를 읽고 쓸 수 있다.

거래대금 급증은 폐기되지 않고 **확증 피처**로 내려간다 — "시장이 이 재료에 반응했는가".

부수 효과로 **뉴스 없이 무료로 착수 가능**해졌다. 공시는 OpenDART 로 무료·10년+·
접수일자 단위 point-in-time 이고 인증키도 이미 있다. 뉴스는 유료(뉴스토어) 또는
수동 36회+(빅카인즈)라 막혔는데, 이제 그것이 착수 조건이 아니다(§4).

## 1. 무엇을 만드는가

한국 주식(KOSPI·KOSDAQ)에서 **2~8주 스윙 후보를 찾아주는 개인용 리서치 툴**.

공시·뉴스로 재료가 발생한 종목 중, 그 재료가 몇 주 갈 것인지를 판정해 근거와 함께
후보를 제시한다. 최종 매매 판단은 사람이 한다.

**한 줄 요약:**

> 재료(공시)가 이벤트를 만들고 → 유형·규모·신선도를 피처로 뽑고 →
> 수급과 시장 반응이 독립 확증하고 → ML 이 D+20~40 초과수익으로 학습하고 →
> 게이트가 심판하고 → **절대 임계를 넘은 것만** 후보로 나온다.

**"확실한 것만."** 날짜당 상위 N 을 억지로 뽑지 않는다. 임계 미달이면 그날은 0건이다(§6).

**나중에 공개 레포로 전환할 계획.** 설계가 이를 전제한다(§9).

## 2. 왜 이 모양인가 — 두 번의 실패에서 온 제약

이 설계는 백지에서 나온 게 아니라 두 번의 부정 결과 위에 서 있다.

**(a) Minervini 리더 시스템 (실패).** 수정주가 미반영 데이터가 만든 아티팩트였다.
분할 조정 후 다시 재니 시가총액 가중 지수를 못 이겼다(+14.0%/Sharpe 0.54 vs +15.5%/0.71).

**(b) 프랍 스윙 엣지 탐색, 2026-07-18 (실패).** 롱온리·1~10일·4~8종목 집중으로
돌파·눌림목·PEAD집중 세 셋업을 심사했고 **셋 다 자기 랜덤-진입 널조차 못 이겼다.**
그 문서의 결론이 남긴 세 갈래:

> (a) 다른 데이터(장중·대체데이터) (b) 일봉에 없는 엣지원 — **촉매/뉴스/재량**
> (c) 분산 PEAD 를 받아들이되 그건 프랍이 아님

**scalp-it 은 (b) 노선이다.** 우연이 아니라 그때 남긴 결론을 따라간다.

여기서 세 가지 강제 조건이 나온다. 위반하면 같은 결과가 나온다:

1. **드리프트를 자르지 않는다.** PEAD-집중이 죽은 직접 원인은 10% 손절 + 10일 캡이
   승자를 자르고 노이즈를 확정한 것. 목표 보유 20~40 거래일, 짧은 캡 금지.
   근거 카드에 손절가를 표시하더라도 그것은 개별 리스크 관리이지 시그널 엑싯이 아니다.
2. **집중하지 않는다.** 4~8 종목은 이미 죽은 영역. 동시 보유 15종목 이상을 전제로 제시한다.
3. **음성대조 없이 아무것도 승격하지 않는다.** 프랍 탐색에서 판별기 역할을 한 것은
   폴드 수가 아니라 **랜덤 널 대비**였다. 표본이 작을수록(§7) 더욱 그렇다.

## 3. 핵심 구조 — 재료가 이벤트, ML 이 학습기

### 이벤트: 공시가 난 (종목, 날짜)

유동성 하한을 통과한 종목에 **공시가 접수된 날**이 이벤트다. 유형으로 미리 거르지
않는다 — 어떤 재료가 먹는지는 사람의 편견이 아니라 데이터가 정해야 한다.
`material_type` 은 **필터가 아니라 피처**다.

단 하나의 예외: **악재 유형은 배제한다.** 롱온리라 공매도로 못 먹고, 후보 리스트에
올려봐야 쓸 데가 없다(§5).

실측 규모(2026-05~07): 상장종목 공시 하루 462건, `(종목, 날짜)` 로 묶으면 약 250건.
3년이면 19만 이벤트. 표본은 넉넉하다.

### 재료 피처: 공시는 유형이 규격화돼 있다

뉴스와 달리 공시는 금융감독원 서식이 제목을 정해 표현이 흔들리지 않는다.
**LLM 없이 규칙만으로 재료 유형을 얻는다.**

| 재료군 | 대표 공시 | 하루 |
|---|---|---|
| 내부자 거래 | 임원·주요주주 특정증권 소유상황보고서 | ~60 |
| 자본조달 | 유상증자·CB·신주인수권·전환가액조정 | ~96 |
| 사업 재료 | 공급계약 · 시설투자 · 기술/인허가 · 투자판단관련주요경영사항 | ~26 |
| 주주환원 | 자사주 취득 · 배당 · 주식소각 | ~13 |
| 악재 | 감사의견·거래정지·소송·실질심사 | ~11 |
| 실적 | 연결재무제표기준 영업(잠정)실적 | ~8 |

**내부자 거래가 가장 많고, 개념상으로도 가장 강한 확증이다** — 회사 내부자가 자기
돈으로 사는 것은 "재료가 진짜인가"에 대한 답이다.

그리고 **우리가 LLM 에게 추정시키려던 피처가 공시에는 사실로 적혀 있다.**
실측 예(에프알텍 073540, 2026-08-14 단일판매·공급계약체결):

```
계약금액 총액   5,584,228,670원
최근 매출액    25,263,688,167원
매출액 대비        22.1%              → "규모 대비"가 추정이 아니라 사실
계약기간      2026-08-12 ~ 2026-11-04  → "지속성"이 추정이 아니라 사실
3년간 동종계약   해당                   → "신선도"가 추정이 아니라 사실
```

### LLM 의 자리 (③층, 나중)

원문 파싱으로 안 나오는 것 — 재료의 맥락, 계약 상대방의 무게, 문장에 묻은 조건성 —
만 LLM 에 맡긴다. **"이거 오를까?"는 묻지 않는다.** 그 답을 믿는 순간 검증이 불가능해진다.
공시 원문은 무료로 받을 수 있으므로 LLM 층도 뉴스 구매 없이 만들 수 있다.

### ML 이 하는 일: 피처와 실제 결과를 대조해 학습

라벨은 가격 데이터에서 공짜로 나온다:

> 공시 접수일 **D+1 시가 진입** → **D+20 ~ D+40 초과수익** (횡단면 평균 대비)

휴장일 접수 공시는 다음 거래일로 이월한다(앞으로만 — 뒤로 당기면 lookahead).

이 구조 덕분에 검증이 표준 지도학습 문제가 된다 — walk-forward, 음성대조, 비용스윕을
kr-quant 게이트로 그대로 적용할 수 있다. LLM 의 주관은 시그널이 아니라 입력일 뿐이다.

**부수 효과: "하루 뛰고 마는 것"이 자동으로 걸러진다.** 라벨이 D+20~40 이므로
당일 급등 후 되돌리는 재료는 학습 과정에서 음수 라벨을 받는다. 규칙으로 배제할 필요가 없다.

### 수급과 시장 반응: 재료와 독립된 두 번째 증거

재료 강도를 공시 텍스트만으로 판단하면 서식의 문구를 읽는 것에 가깝다.
시장이 실제로 어떻게 반응했는지가 이를 보완한다.

| 피처 | 의미 |
|---|---|
| 기관·외국인 순매수 | 스마트머니가 따라 들어왔는가 |
| **거래대금 급증 배수** | **시장이 이 재료에 반응했는가** (rev1 의 이벤트가 여기로 내려왔다) |
| 대차잔고·공매도 변화 | 반대 베팅이 늘었는가 (2024-05~ 만 존재) |

**검증 가능한 핵심 가설:** "재료가 난 종목 중, 시장과 스마트머니가 따라붙은 것만
20~40일을 간다." 두 축이 독립이라 과적합 검출이 쉽다.

수급은 장마감 후 확정이므로 D+1 진입 기준으로 시점 안전하다.

### 층별 기여도 분리

베이스라인부터 쌓아 각 층이 값을 하는지 따로 판정한다:

```
① 수급 + 시장반응 단독      ← 베이스라인. 재료 내용 없이 얼마나 나오는가
② + 공시 유형·구조화 피처   ← 무료, LLM 없이. 재료가 값을 하는가
③ + LLM (공시 원문)         ← LLM 이 ②를 이기는가. 여전히 무료
④ + 뉴스                    ← 공시가 못 잡는 재료를 메우는가. 유료/수동
```

**각 층은 앞 층을 이겨야 승격한다.** ②가 ①을 못 이기면 재료 축 자체가 약한 것이고,
③에 갈 이유가 없다. ③이 ②를 못 이기면 LLM 을 쓸 이유가 없다. ④는 ②·③이 값을
했을 때만 지출을 검토한다.

**이 순서가 곧 지출 순서다** — ①②③은 전부 무료이고, 돈이 드는 ④는 맨 끝이다.

## 4. 데이터 소스

| 용도 | 소스 | 상태 |
|---|---|---|
| **공시 (①②③층의 재료 소스)** | **OpenDART** | **무료**, 10년+, 접수일자 point-in-time. 인증키 3개 이미 보유(`quant-airflow/.env`). `list.json` 검색 + `document.xml` 원문 |
| 가격·수급·신용·공매도 | `quant-airflow` → TimescaleDB | 매일 적재 중 |
| 시세·수급 API | `kiwoom-rest-api` (자체) | 182 REST + 19 실시간 WebSocket. **뉴스 엔드포인트는 없음** |
| 검증 프레임워크 | `kr-quant` | walk-forward · DSR · 음성대조 · 비용스윕 |
| 뉴스 (④층, 나중) | 뉴스토어 / 빅카인즈 / `krx-news-rest-api` | 아래 참조 |

### rev2 결정 — 공시로 착수하고, 뉴스는 뒤로 미룬다

뉴스 경로를 전부 재보니 착수 조건으로 삼기 어려웠다.

| 경로 | 과거 데이터 | 비용 | 판정 |
|---|---|---|---|
| 빅카인즈 웹 | 있음(본문 200자) | 무료지만 **수동 36회+** | 1회 20,000건 상한. 게다가 요청 기간 앞부분이 통째로 잘린다(8/10~8/17 요청에 8/10·8/11 소실 실측) |
| 뉴스토어 API | 10년, **본문 전문** | **유료** (견적제) | 검증 전 지출은 이 프로젝트가 두 번 실패한 순서 |
| `krx-news-rest-api` | **없음** (Redis TTL 1시간) | 무료 | 앞으로만 가능 |

필터로 부피를 줄이려 했으나 **깨끗한 레버가 없었다.** 실측(2만 건 실물):
경제 기사의 50.1% 가 이미 상장사를 언급하고, 분류·언론사·키워드 어느 축도 거의 비례로
자른다(예: 상위 20개 매체 → 다운로드 69%, 종목기사 76% 보존). 이벤트 종목 기사는
전체의 6.6% 인데 그 6.6% 를 집어낼 필터가 없다.

**DART 는 이 문제가 전부 없다.** 무료·10년+·접수일자 단위 point-in-time·키 보유.
그래서 재료 소스를 공시로 바꾸고 뉴스는 ④층으로 미룬다.

**뉴스의 남은 역할:** 공시가 못 잡는 재료 — 테마·정책·해외 수요·애널리스트 리포트·루머.
②③층이 값을 했을 때만 지출을 검토한다.

**여전히 유효한 권고 — `krx-news-rest-api` 영구 저장.** 유료 경로를 안 쓰기로 하면
이것이 **유일한 뉴스 축적 경로**다. 지금 시작하지 않으면 6개월 뒤에도 데이터가 없다.
scalp-it 밖의 변경이라 사용자 결정 사항이다.

**직접 크롤러를 새로 짜지 않는다.** 네이버·언론사 직접 크롤링은 ToS·저작권 리스크가
공개 전환 계획과 충돌한다. 빅카인즈 웹 다운로드 자동화도 유료 API 우회라 하지 않는다.

## 5. 유니버스와 이벤트

**고정 종목 리스트가 아니라 재료가 유니버스를 정한다.** 공시가 난 종목이 그날의
후보 풀이다. 소형주 재료도 자연스럽게 잡힌다.

**point-in-time 유동성 하한(직전 20거래일 평균 거래대금 50억)을 건다.** PEAD 검증에서
이 조건 없이는 소형주 꼬리가 노이즈를 주입해 시그널이 음수로 뒤집혔다.

**악재 유형은 배제한다.** 롱온리라 공매도로 못 먹는다. 배제는 필터이고, 나머지 유형은
전부 피처로 남는다.

**휴장일 접수 공시는 다음 거래일로 이월한다.** 앞으로만 옮긴다 — 토요일 공시를
금요일에 알 수는 없다. 원 접수일은 보존해 근거 카드에 표시한다.
(뉴스에서 같은 버그로 주말 기사가 통째로 사라진 적이 있다.)

## 6. 출력 — "확실한 것만"

학습·평가와 운영 출력을 분리한다.

```
학습·검증:  모든 이벤트 · 날짜당 상위 N   (상대 기준, 성과 측정용)
운영 출력:  절대 임계 통과분만            (기준 미달이면 그날은 0건)
```

**날짜당 상위 N 을 억지로 뽑지 않는다.** 재료가 시원찮은 날에도 N 건이 나오면 그건
"그날 최선"이지 "확실한 것"이 아니다. 임계 미달이면 **"오늘은 후보 없음"** 을 출력한다.

**임계값은 구조에서 정한다, 성과에서가 아니다.** 학습 구간에서 **동시 보유 기대치가
15~25종목이 되는 지점**으로 잡는다. 스펙 §2 의 분산 하한(15 이상)과 "확실한 것만"의
상한을 동시에 만족하는 구간이다. 보유 40거래일 기준 하루 0.4~0.6건 — 이틀에 한 번꼴.
검증 구간에서는 학습 구간에서 정한 값을 그대로 적용한다.

**`top_n` 은 동시 보유 기준이다.** 스펙 §2 의 "동시 보유 15종목 이상"을 "날짜당 15종목"
으로 구현했다가 `selection_ratio` 가 1.0 이 되어 선택이 일어나지 않았다.
동시 보유 ≈ `top_n × hold_end`. → `docs/research/2026-08-17-topn-preregistration.md`

### 필수 진단: 예측값 십분위 단조성

"확실한 것"이 존재하려면 **예측값이 클수록 실제 초과수익이 좋아야 한다.**
그래서 층 비교와 별개로 반드시 본다:

> 예측값 십분위별 실제 초과수익이 단조 증가하는가

상위 10% 가 5분위보다 낫지 않으면 절대 임계를 걸 근거가 없다. 층이 널을 이겨도
예측값이 단조롭지 않으면 "상위만 골라 들어간다"가 성립하지 않는다.

## 7. 표본 크기 제약 — 모델은 단순해야 한다

공시 이벤트는 `(종목, 날짜)` 기준 하루 약 250건, 3년이면 19만 건이다. 그러나
라벨 구간(D+20~40)이 겹치고 같은 날 이벤트끼리 시장 상관이 있어
**실효 독립 표본은 훨씬 적다.**

강제 조건:

- 피처 **10~20개**, 모델은 **GBM 또는 로지스틱 회귀** 수준
- **딥러닝·대규모 앙상블 금지** — 이 표본 크기에서는 과적합 기계
- **음성대조 게이트 필수** — 표본이 작을수록 우연히 좋아 보이기 쉽다
- 사전등록: 파라미터 그리드를 돌리기 전에 config 를 확정하고 기록

## 8. PEAD 의 위치

이 레포의 중심이 아니다. 두 자리에 남는다:

1. **모델 피처 하나** — 실적 서프라이즈 축
2. **비교 벤치마크** — 재료 모델이 이미 검증된 PEAD(Sharpe ~0.8, t≈2.2)를 이기는가

**rev2 에서 PEAD 의 의미가 커졌다.** PEAD 는 "실적 발표라는 재료 → 그 후 드리프트"
구조이고, rev2 는 그 구조를 실적 밖의 재료 전체로 넓힌 것이다. 즉 이 프로젝트는
**PEAD 의 일반화가 성립하는지**를 묻고 있다. PEAD 가 벤치마크인 이유가 여기 있다 —
같은 구조의 검증된 사례이기 때문이다.

PEAD 자체를 스윙으로 이식하는 작업은 여전히 이 스펙 범위 밖이다.

## 9. 레포 경계와 모듈

### 기존 스택과의 관계

```
quant-airflow        수집 · 적재       → TimescaleDB (가격·수급·신용·공매도)
krx-news-rest-api    뉴스·공시 수집    → 실시간 (+ 영구저장 추가 필요)
kiwoom-rest-api      시세·수급·주문    → 182 REST + WebSocket
kr-quant             검증 프레임워크   → walk-forward · DSR · 음성대조
scalp-it             제품              → 주간 후보 리스트 + 근거 카드
```

kr-quant 는 "검증 프레임워크지 스크리너 제품이 아니다"라는 정체성으로
2026-08-16 에 스크리너 CLI 7종을 제거했다. scalp-it 이 그 빈자리인 **제품**이다.

### 모듈

| 모듈 | 책임 | 의존 |
|---|---|---|
| `adapters/` | 외부 시스템 접근을 여기 한 곳에 격리 (DB · DART · 뉴스) | — |
| `dart/` | 공시 유형 분류 · 원문 파싱 · 로컬 저장 | adapters |
| `news/` | 기사 수집·종목 매핑·중복 제거·거래일 이월 (④층) | adapters |
| `score/` | LLM 배치 피처 추출 (provider 교체 가능) | dart, news |
| `features/` | 수급 · 공시 · 뉴스 · LLM 피처와 라벨 결합 | dart, news, adapters |
| `model/` | 학습·추론 (GBM/로지스틱) | features |
| `validate/` | 게이트 · 층 비교 · 십분위 단조성 | model |
| `report/` | 후보 리스트 · 근거 카드 · 전진 기록 | model, dart |

**`adapters/` 규칙:** kr-quant·kiwoom·krx-news 에 손을 뻗는 코드는 전부 여기에만 둔다.
나머지 모듈은 그 레포들이 존재하는지도 모른다. 나중에 완전 독립 레포로 가려면
어댑터만 자체 구현으로 갈아끼우면 된다. 공개 전환 시에도 이 경계가 그대로 도움이 된다.

**`validate/` 규칙:** scalp-it 은 자기 검증을 하지 않는다. 판정은 전부 kr-quant 게이트를
통과해야 하고, 통과한 것만 운영에 등록된다. 스크리너 안에 백테스트를 넣으면
반드시 자기 정당화를 시작한다.

### LLM provider 추상화

`score/` 는 provider 인터페이스 뒤에서 동작한다. Gemini / GPT / Claude 를 환경변수로 교체.

- 기본은 **최저가 등급**(Flash-Lite 급). 기사당 작업이 "제목+리드 읽고 고정 스키마 채우기"라
  추론 난이도가 낮다. 무거운 모델이 필요한 종류의 일이 아니다.
- 표본 수백 건만 상위 모델로 돌려 피처 품질을 대조한다. 차이가 없으면 싼 것으로 확정.
- 실제 단가는 착수 시점에 확인한다. 배치 API 할인 적용 검토.

### 공개 전환 전제

- **데이터는 절대 커밋하지 않는다.** 빅카인즈 재배포 금지, 기사 저작권. 구조로 강제(.gitignore + CI 체크).
- API 키·계좌 정보는 환경변수로만.
- 어댑터 경계 덕분에 코드만 공개하고 데이터·자격증명은 로컬에 남는다.

## 10. 범위

### 1차 범위 안 (전부 무료·자동)

- OpenDART 공시 수집 (`list.json`, 3개월 구간 분할, 키 3개 로테이션)
- 공시 유형 규칙 분류, 악재 배제, 거래일 이월
- 공시 피처 (건수·급증 배수·유형 비율·신선도·내부자)
- 수급·거래대금 피처 결합, D+20~40 라벨 생성
- 층 비교 ① 수급+시장반응 → ② +공시
- 게이트 심판 4종 + 하방 회피 + 선별도 + **십분위 단조성**
- PEAD 대비 벤치마크
- 후보 리스트 + 근거 카드, 절대 임계 적용
- 오늘부터의 전진 기록(forward log)

### 2차 (①②가 값을 했을 때, 여전히 무료)

- 공시 원문(`document.xml`) 수집과 구조화 파싱 — 계약금액·매출액 대비·계약기간
- ③층 LLM 피처 (공시 원문 대상)

### 범위 밖 (나중)

- **④층 뉴스** — ②③이 값을 했을 때만 지출/수작업 검토
- 실시간 WebSocket 모니터링, 진입 타이밍
- **조건검색** — 사람이 만든 조건식은 과적합 유입 경로
- 주문 자동 실행
- **포지션 예산 시뮬레이션** — 현재 성과 지표는 시그널 품질 측정이지 포트폴리오가
  아니다. 승격 판정 전에 별도로 필요하다
- **데이트레이딩** — 검토했으나 접었다. 분봉·틱 과거 데이터가 없어 검증이 불가능하고,
  1~10일 지평은 2026-07-18 프랍 탐색에서 이미 세 셋업이 랜덤 널조차 못 이겼다

## 11. 성공 기준

1. **층별 기여도가 분리 측정됐다** — ①수급 / ②+공시 / ③+LLM 각각의 성과
2. **음성대조를 이겼다** — 랜덤 진입 널 대비 유의하게 우월
3. **walk-forward 재현** — 모든 폴드에서 널 대비 우위, 손 안 댄 최종창에서도 양수
4. **비용을 견딘다** — 왕복 46bp 이상에서 여전히 양수
5. **예측값이 단조롭다** — 십분위 상위가 실제로 더 좋다. 아니면 "확실한 것만"이 허구다
6. **PEAD 대비 판정이 나왔다** — 이기든 지든 명시적으로

**부정 결과도 성공이다.** "공시 재료는 한국 시장 2~8주 지평에서 재현되는 엣지가
아니다"라는 결론이 나오면 기록하고 끝낸다. 세 번째로 아티팩트를 실전에 올리는 것보다
낫고, 뉴스에 돈을 쓰기 전에 알게 되는 것이 이 순서의 목적이다.

## 13. 열린 질문 (구현 계획 단계에서 해소)

  소유상황보고서(하루 60건), 연결재무제표기준 영업(잠정)실적, 배당·주식소각,
